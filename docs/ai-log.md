# AI Log

## Призначення журналу

Цей файл містить детальний журнал взаємодії під час проєктування та
ініціалізації TypeScript-проєкту Hello World із npm scripts, Vitest і
GitHub Actions.

## 1. Запити

### 1.1. Документація проєкту

Було поставлено завдання підготувати три Markdown-файли:

- `README.md` із даними студентки Стахової Валерії Юріївни, групою КІ-406,
  варіантом 6, описом Hello World та інструкцією запуску AI-агента;
- `docs/architecture.md` з архітектурою агента, його skills, commands,
  передачею даних між етапами та обробкою помилок;
- `agents/build-engineer.agent.md` як Agent Manifest для ролі Build Engineer.

У маніфесті було зафіксовано правила роботи з файлами, заборону автоматичного
видалення файлів і публікації секретів, а також критерії успішного завершення.

### 1.2. Skills

Наступним запитом було підготовлено три інструкції навичок у каталозі
`.github/skills/`:

- `project-scaffold/SKILL.md` — створення мінімального TypeScript Hello World,
  структури каталогів, `README.md` і `.gitignore`;
- `build-and-test/SKILL.md` — налаштування npm scripts, TypeScript-збірки та
  юніт-тестів через Vitest;
- `github-actions/SKILL.md` — створення CI workflow з матрицею Windows, Linux
  і macOS.

Для кожної навички були визначені умови застосування, вхідні параметри,
очікувані файли, перевірки та дії у випадку помилки.

### 1.3. Commands

Після цього було створено шість команд у каталозі `prompts/`:

- `git-init.prompt.md` — перевірка Git і створення або доповнення
  `.gitignore`;
- `create-project.prompt.md` — виклик `project-scaffold`;
- `create-build.prompt.md` — виклик `build-and-test`;
- `create-actions.prompt.md` — виклик `github-actions`;
- `check.prompt.md` — read-only перевірка структури, збірки, тестів і YAML;
- `init.prompt.md` — оркестратор, який запускає попередні команди послідовно.

Команди спроєктовано ідемпотентними: повторний запуск не повинен руйнувати
наявні файли, дублювати конфігурацію або скасовувати зміни користувача.

## 2. Запуск оркестратора

Для виконання оркестратора було передано два ключові файли:

- `agents/build-engineer.agent.md` — маніфест ролі Build Engineer;
- `prompts/init.prompt.md` — інструкція оркестратора.

Запит полягав у тому, щоб агент проаналізував пов'язані skills і commands,
послідовно виконав ініціалізацію та згенерував код, тести й CI/CD-конвеєр.
Очікуваний порядок етапів був таким:

1. `git-init`;
2. `create-project`;
3. `create-build`;
4. `create-actions`;
5. `check`.

Окремо було уточнено, що проєкт має містити модуль арифметики та тест
`tests/math.test.ts`, тому до базового Hello World було додано `src/math.ts`.

## 3. Важливі відповіді та створені файли

У результаті були створені необхідні файли проєкту:

- `package.json` із npm scripts:
  `build`, `start`, `test` і `test:run`;
- `tsconfig.json` зі строгою конфігурацією TypeScript;
- `src/index.ts` із функцією та виведенням `Hello, World!`;
- `src/math.ts` із функцією `add`;
- `src/index.test.ts` для перевірки Hello World;
- `tests/math.test.ts` із тестами додавання через Vitest;
- `.gitignore` для залежностей, build-артефактів і локальних секретів;
- `.github/workflows/ci.yml` із матрицею `windows-latest`,
  `ubuntu-latest` і `macos-latest`.

Також було створено `docs/usage.md` з інструкціями запуску AI-агента та
локальної перевірки.

Статичні перевірки підтвердили наявність очікуваних файлів, коректний JSON у
`package.json` і `tsconfig.json`, наявність потрібних CI-кроків та відсутність
помилок `git diff --check`.

## 4. Помилки

Під час спроби агента виконати встановлення залежностей команда:

```text
npm install
```

завершилася помилкою середовища:

```text
The term 'npm' is not recognized
```

Це означає, що Node.js/npm не були доступні в `PATH` поточного середовища.
Додатковою перевіркою було підтверджено, що команди `node`, `npm` і `npm.cmd`
не знаходяться системою.

Через цю інфраструктурну помилку етапи, які потребують встановлення
залежностей і виконання runtime-команд, отримали статус **`blocked`**:

- `create-project` — файли створені, але `npm install` не виконано;
- `create-build` — конфігурація і тести створені, але Vitest не запущено;
- `check` — статичні перевірки виконані, але `npm ci`, build і тести не
  підтверджені runtime-запуском.

Агент не маскував цю помилку успішним статусом і не створював вигаданих
результатів тестування.

## 5. Прийняті рішення

Було прийнято рішення виконати команди локально в терміналі розробника, де
встановлено Node.js та npm:

```bash
npm install
npm run build
npm run test
```

Це є рекомендованим наступним кроком для повної перевірки згенерованого коду:
`npm install` встановлює залежності, `npm run build` перевіряє TypeScript-
збірку, а `npm run test` запускає Vitest.

У поточному сеансі середовище не розпізнало `npm`, тому фактичне успішне
виконання цих трьох команд тут не підтверджено. Водночас файли коду були
згенеровані без виявлених статичних помилок, а після встановлення Node.js/npm
команди мають бути виконані локально з перевіркою exit code та звіту Vitest.
