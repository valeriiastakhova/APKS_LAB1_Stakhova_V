# Архітектура AI-агента

## 1. Призначення

Агент призначений для безпечної автоматизації задач Build Engineer у
TypeScript-проєкті Hello World. Він не є автономною системою, що довільно
змінює репозиторій: агент діє в межах запиту користувача, маніфесту та
доступних інструментів.

Архітектура вирішує такі проблеми:

- зменшує кількість ручних кроків під час встановлення залежностей, збірки й
  тестування;
- уніфікує запуск команд через npm scripts;
- виявляє помилки TypeScript і Vitest на ранньому етапі;
- зберігає трасованість: кожен етап має вхід, команду, результат і статус;
- запобігає випадковому видаленню файлів та витоку секретів;
- повертає користувачу зрозумілий звіт замість прихованого або часткового
  успіху.

## 2. Компоненти

```text
Користувач
    |
    v
Оркестратор агента
    |
    +--> Контекст репозиторію
    |      (package.json, tsconfig, src, tests)
    |
    +--> Skills
    |      (scaffold, build-and-test, CI)
    |
    +--> Commands
    |      (npm install/build/test/start)
    |
    v
Валідація результату --> Звіт користувачу
```

### Оркестратор

Оркестратор керує послідовністю етапів, зберігає статуси та не переходить до
наступного кроку, якщо обов'язкова попередня перевірка завершилася помилкою.
Він також перевіряє, що команда належить до дозволеного переліку, а зміни
обмежені робочим каталогом проєкту.

### Skills

Проєкт використовує такі skills:

- **`project-scaffold`** — аналізує структуру проєкту та допомагає підготувати
  мінімальні файли TypeScript, `package.json` і `tsconfig.json`;
- **`build-and-test`** — визначає правильні npm scripts, запускає збірку,
  Vitest і перевіряє коди завершення;
- **`github-actions`** — за потреби узгоджує локальні команди з CI, але не
  публікує код або секрети без явного запиту.

### Commands

Основні команди — це npm scripts, оголошені в `package.json`:

| Команда | Призначення |
| --- | --- |
| `npm install` | встановити залежності |
| `npm run build` | виконати TypeScript-збірку |
| `npm test` | запустити Vitest у локальному режимі |
| `npm run test:run` | виконати одноразовий тестовий прогін для CI |
| `npm start` | запустити зібраний Hello World |
| `npm run dev` | запустити режим розробки, якщо він налаштований |

Агент спочатку читає `package.json` і використовує фактично наявні scripts,
а не вигадує команду. Якщо необхідного script немає, він повідомляє про це й
пропонує мінімальну зміну замість мовчазного обходу проблеми.

## 3. Передача даних між етапами

Оркестратор передає між етапами структурований контекст:

```ts
type AgentContext = {
  request: string;
  workspace: string;
  packageScripts: Record<string, string>;
  changedFiles: string[];
  commandResults: Array<{
    command: string;
    exitCode: number;
    stdout: string;
    stderr: string;
  }>;
  status: "planned" | "running" | "passed" | "failed" | "blocked";
};
```

Потік даних:

1. **Discover** читає запит, список файлів і `package.json`.
2. **Plan** перетворює запит на план із дозволених операцій.
3. **Implement** за потреби вносить мінімальні зміни в TypeScript або npm
   scripts і додає відповідні тести.
4. **Build** виконує `npm run build`, передаючи stdout, stderr і exit code до
   контексту.
5. **Test** виконує `npm run test:run` і додає результати Vitest.
6. **Report** формує підсумок: змінені файли, команди, помилки та наступні
   дії.

Секрети не передаються в текстові логи: змінні середовища маскуються, а
значення токенів, паролів і ключів ніколи не виводяться у звіт.

## 4. Обробка помилок

Помилки поділяються на чотири групи:

1. **Вхідні** — відсутній `package.json`, невідома задача або неповний
   контекст. Оркестратор зупиняється і просить уточнення.
2. **Конфігураційні** — відсутні npm scripts або залежності. Агент повідомляє
   точну причину й пропонує відтворюваний крок виправлення.
3. **Збірки та тестів** — ненульовий exit code, помилки TypeScript або
   падіння Vitest. Оркестратор зберігає діагностику, не маскує помилку і не
   оголошує задачу успішною.
4. **Безпеки та доступу** — спроба видалення, вихід за межі workspace або
   виявлений секрет. Операція блокується, а користувачу повертається
   попередження.

Для кожної команди встановлюється тайм-аут. Після тимчасової помилки агент
може повторити лише безпечну ідемпотентну команду (наприклад, тестовий
прогін), але не повторює небезпечні операції автоматично. Часткові зміни
перераховуються у звіті; відкат можливий лише за явним рішенням користувача.

## 5. Критерій успіху

Задача вважається успішною, коли потрібні зміни перевірені, `npm run build`
завершився з кодом `0`, `npm run test:run` завершився з кодом `0`, а агент
надав звіт без розкриття секретів. Якщо будь-яка умова не виконана, статус
має бути `failed` або `blocked`, а не `passed`.
