# Command: git-init

## Мета

Безпечно підготувати Git-контекст проєкту, перевірити поточний стан,
створити або доповнити `.gitignore` та показати результат користувачу.

## Передумови

- Команда запускається з кореня workspace.
- Доступний Git.
- Користувач має права читання та запису в workspace.
- Перед змінами потрібно виконати `git status --short --branch`.
- Існуючі зміни користувача не можна скасовувати або перезаписувати.

## Дії

1. Визнач корінь workspace і перевір, чи існує `.git`.
2. Якщо Git-репозиторій відсутній, виконай `git init` лише в корені workspace.
3. Якщо `.gitignore` відсутній, створи його з базовими правилами:

   ```gitignore
   node_modules/
   dist/
   coverage/
   .env
   .env.*
   !.env.example
   ```

4. Якщо `.gitignore` уже існує, прочитай його та додай лише відсутні правила.
   Не дублюй рядки й не видаляй користувацькі правила.
5. Повтори `git status --short --branch` і покажи стан без виконання commit,
   push або автоматичного staging.

Повторний запуск має бути ідемпотентним: не створюй другий Git-репозиторій,
не дублюй правила та не змінюй інші файли.

## Очікувані файли

- `.gitignore` — створений або доповнений без дублювань;
- `.git/` — створений лише якщо репозиторій справді був відсутній.

Жодні інші файли не повинні змінюватися.

## Команди перевірки

```bash
git rev-parse --show-toplevel
git status --short --branch
git check-ignore -v node_modules dist coverage .env
```

Додатково виконай `git diff --check`, якщо `.gitignore` був змінений.

## Повідомлення про помилку

- `Помилка: workspace не є коренем проєкту або недоступний для запису.`
- `Помилка: git init завершився невдало: <stderr>.`
- `Помилка: не вдалося створити або оновити .gitignore: <причина>.`
- `Помилка: перевірка Git завершилася невдало: <stderr>.`

У разі помилки зупинись, не видаляй частково створені файли та вкажи, який
крок завершився невдало.
