# Command: check

## Мета

Виконати read-only перевірку структури проєкту, конфігурації, TypeScript-
збірки, Vitest і GitHub Actions workflow без зміни файлів.

## Передумови

- Визначено корінь workspace.
- Доступні Git, Node.js і npm.
- Команда має право читати файли та запускати локальні перевірки.
- Якщо є `package-lock.json`, залежності можна встановити через `npm ci`.
- Усі дії цієї команди є лише для читання або виконання перевірок.

## Дії

1. Перевір наявність `src/`, `package.json`, `tsconfig.json`, тестів,
   `.gitignore` і `.github/workflows/ci.yml`.
2. Прочитай `package.json`, перевір scripts `build` і `test:run`.
3. Перевір JSON/YAML структуру без редагування.
4. Запусти `npm ci`, якщо існує lock-файл.
5. Запусти `npm run build`.
6. Запусти `npm run test:run`.
7. Перевір workflow на матрицю Windows, Linux, macOS і потрібні npm-кроки.
8. Зафіксуй Git-стан до та після перевірки й підтвердь, що файли не змінені.

Повторний запуск не повинен створювати, змінювати чи видаляти файли. Не
запускай `npm install`, якщо це може змінити lock-файл; для CI-перевірки
використовуй `npm ci`.

## Очікувані файли

Команда не створює і не змінює файлів. Вона лише перевіряє наявність:

- `src/index.ts`;
- `package.json`;
- `package-lock.json`;
- `tsconfig.json`;
- `src/index.test.ts`;
- `.gitignore`;
- `.github/workflows/ci.yml`.

## Команди перевірки

```bash
git status --short
npm ci
npm run build
npm run test:run
git diff --check
git status --short
```

Перевір також YAML workflow валідатором GitHub Actions або локальним linter-ом.
Фінальний Git-стан має збігатися зі станом до перевірки, якщо не було
зовнішніх змін.

## Повідомлення про помилку

- `Перевірка не пройдена: відсутній файл <шлях>.`
- `Перевірка не пройдена: npm ci завершився з кодом <code>: <stderr>.`
- `Перевірка не пройдена: збірка TypeScript завершилася невдало: <stderr>.`
- `Перевірка не пройдена: Vitest має невдалі тести: <звіт>.`
- `Перевірка не пройдена: ci.yml не відповідає вимогам матриці: <опис>.`
- `Перевірка не пройдена: read-only команда виявила зміни у файлах: <список>.`

У разі помилки нічого не виправляй автоматично: поверни діагностику,
невдалу команду та exit code.
